# 内链入链价值衰减监控方法

{% raw %}

## 什么是内链入链价值衰减

某个页面的“[内链](./internal-link-anchor-context-window.html)入链”，是站内其他 URL 指向该页面的链接。监控时不能只统计链接条数，因为数量不变并不代表传递价值不变。例如：

- 来源页面被删除、重定向或改为不可索引；
- 链接从正文移动到页脚、标签云等重复区域；
- 来源页面的站内重要性或抓取频率下降；
- 链接被添加 `rel="nofollow"`，或只能通过搜索引擎难以执行的脚本生成；
- 目标 URL 开始重定向、返回错误状态，或 canonical 指向其他页面；
- 锚文本从明确主题词变为“点击这里”等弱描述文本。

搜索引擎不会公开单条内链的实际权重，因此所谓“价值”只能通过可观测指标建立代理模型。监控的目的不是计算真实 PageRank，而是及时发现链接关系、来源质量和技术可达性的异常变化。

## 建立可比较的内链快照

建议按天或按周完整抓取网站，并保存“链接边”级别的数据，而不是只保留每个页面的汇总结果。一条链接边至少应包含以下字段：

| 字段 | 用途 |
|---|---|
| `crawl_date` | 区分不同时间的快照 |
| `source_url` | 链接来源页面 |
| `target_url` | 链接目标页面 |
| `source_status` | 来源页面 HTTP 状态 |
| `target_status` | 目标页面 HTTP 状态 |
| `anchor_text` | 判断[锚文本](./seo-internal-link-strategy.html)是否发生变化 |
| `link_position` | 正文、导航、侧栏、页脚等位置 |
| `rel` | 记录 nofollow、ugc、sponsored 等属性 |
| `source_indexable` | 来源页面是否允许索引 |
| `source_canonical` | 来源页 canonical 指向 |
| `redirect_target` | 识别链接是否经过重定向 |
| `discovery_type` | 原始 HTML 或渲染后发现 |

抓取前要统一 URL 规则，例如处理协议、主机名、尾斜杠、默认首页和追踪参数。`/page` 与 `/page?utm_source=x` 如果实际是同一内容，不应被错误计算为两个目标。

同时保留两套结果较稳妥：

1. **原始链接记录**：同一来源页面出现三次相同链接，也完整保存；
2. **去重链接记录**：按 `source_url + normalized_target_url` 去重，用于计算独立来源页面数。

如果网站大量依赖 JavaScript，应分别记录原始 HTML 与渲染后链接。仅在浏览器渲染后出现的链接不一定无效，但其发现和处理条件与普通 `<a href>` 链接不同，值得单独观察。

## 用代理指标计算入链价值

可以为每条内链设置一个可解释的评分，再汇总为目标页面的入链价值。一个简化模型如下：

```text
单条链接分值 =
来源重要性 × 可抓取系数 × 位置系数 × 属性系数 × 目标可用系数

目标页面入链分值 = 所有独立来源链接分值之和
```

各部分可以这样定义：

- **来源重要性**：使用站内 PageRank、来源页自身独立入链数、服务器日志中的搜索引擎抓取频率等指标归一化计算；
- **可抓取系数**：来源页返回 200、未被 robots.txt 阻止且页面可索引时取较高值；
- **位置系数**：正文相关段落通常高于模板页脚，但具体权重应根据网站结构校准；
- **属性系数**：普通链接与带 `nofollow` 的链接分开统计，不必武断地把后者设为绝对零；
- **目标可用系数**：目标返回 200 且 canonical 自指时较高，重定向、软 404 或错误状态应降低。

例如，可以先采用一组便于解释的内部参数：

```text
正文链接：1.0
侧栏链接：0.6
导航链接：0.5
页脚链接：0.3

目标返回 200：1.0
目标 301/302：0.4
目标 4xx/5xx：0
```

这些数字不是搜索引擎官方权重，只是监控尺度。真正重要的是同一套规则持续使用，使不同日期的数据可以比较。大型网站还应按页面类型分别建立基线，避免产品页、栏目页和[文章](./seo-related-content-links.html)页使用同一个阈值。

## 判断是否真的发生衰减

单日下降可能来自抓取失败、发布波动或临时服务器错误，不宜立即判定为结构问题。建议同时观察绝对变化、相对变化和持续时间。

常用指标包括：

- 独立内链来源页面数；
- 有效 200 来源数；
- 正文入链数及其占比；
- 来源页平均站内重要性；
- 指向重定向 URL 的链接比例；
- 不可索引来源链接比例；
- 目标页综合入链分值；
- 搜索引擎日志中的目标页抓取频率；
- Google Search Console 中目标页的展示、点击和索引状态变化。

衰减率可以用稳定基线计算：

```text
衰减率 =（近 4 周中位数 - 当前分值）/ 近 4 周中位数
```

使用中位数比直接与前一天比较更能抵抗异常值。一个实用的预警条件是：

- 综合分值下降超过 25%；
- 同时损失至少 5 个独立来源页面；
- 异常连续出现在两次完整抓取中。

对于核心栏目、转化页或时效性页面，可设置更严格的独立阈值。低基数页面则应以绝对损失为主：一个只有两条入链的页面减少一条，降幅虽为 50%，却未必需要最高级别告警。

## 从告警定位具体原因

产生告警后，应先对比链接边，而不是直接补链接。将当前快照与基线快照按“来源 URL＋目标 URL”关联，可把变化分为新增、删除和属性变化三类。

排查顺序可以是：

1. **检查抓取完整性**
   确认本次抓取的 URL 数量、状态码分布和抓取深度是否正常，排除认证失败、限速或渲染故障。

2. **检查来源页面**
   查看丢失链接的来源是否被删除、重定向、加上 `noindex`，或已不再进入主要导航路径。

3. **检查页面模板**
   如果大量不同页面同时丢失相同链接，通常与导航、面包屑、相关推荐或页脚模板发布有关。

4. **检查目标 URL**
   确认目标是否改版、更换路径、形成重定向链，或 canonical 意外指向其他页面。

5. **检查链接语境**
   对比锚文本、链接位置和周边文本，判断链接是否从相关正文移入通用模块。

6. **结合日志与搜索数据验证**
   若入链分值下降后，搜索引擎抓取频率、展示量也持续变化，应提高处理优先级；但相关性不能直接证明因果关系。

## 修复与持续监控策略

修复应针对衰减原因，而不是机械增加链接数量。旧 URL 已迁移时，优先更新站内链接使其直接指向最终地址，减少不必要的重定向跳转；模板误删则恢复真正有导航意义的入口；[孤立页面](./seo-orphan-page-fix.html)应从相关栏目、主题页或正文中建立自然链接。

不要为了恢复分值在所有页面批量添加关键词锚文本。大量无关、重复的模板链接可能降低可用性，也无法保证索引或排名改善。更合理的做法是让链接帮助用户继续阅读，并准确表达目标页面内容。

监控系统至少应保留 8～12 周历史数据，并在站点迁移、导航改版、URL 规则调整和大规模内容清理前后增加抓取频率。告警报告最好直接列出受影响目标、丢失来源、状态变化和模板类型，让编辑与开发人员能够快速复现。

内链价值衰减监控的核心，是持续保存可比较的链接关系，并把“数量减少”进一步拆解为来源质量、技术可达性和链接语境的变化。只要评分规则稳定、阈值符合站点规模，便能在结构问题扩大之前发现风险，同时避免把正常内容波动误判为 SEO 故障。
