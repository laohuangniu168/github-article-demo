# 百度蜘蛛深层页面抓取优化方法

{% raw %}

深层页面通常是指从首页或主要入口需要多次点击才能到达的内容，例如多级分类下的文章、商品详情、分页列表和历史内容。它并不等同于 URL 中目录层级多：`/a/b/c.html` 如果首页直接链接，实际抓取深度可能只有一层。

优化的核心不是单纯“多提交链接”，而是让百度蜘蛛能够稳定发现 URL、顺利访问页面，并把有限的抓取资源更多用于有价值的内容。

## 先确认问题出在发现、抓取还是收录

深层页面没有出现在搜索结果中，不一定是蜘蛛没有抓取。应先区分三个环节：

1. **未发现**：页面缺少可爬取入口，蜘蛛不知道 URL 存在。
2. **已发现但抓取不足**：入口太深、服务器不稳定，或无效 URL 消耗了抓取资源。
3. **已抓取但未收录**：页面重复、内容单薄、状态异常，或者规范化信号不清晰。

可以在百度搜索资源平台中查看索引、抓取异常、资源提交等数据；具体可用工具和配额以站点后台显示为准。对于单个页面，也可以使用搜索命令做辅助检查：

```text
site:example.com/page-url
```

但 `site:` 结果并非完整索引清单，不能单独作为是否收录的最终判断。

服务器访问日志更适合确认实际抓取情况。以 Nginx 日志为例，可以先筛选包含百度蜘蛛标识的请求：

```bash
grep -i "Baiduspider" access.log
```

进一步统计被请求最多的路径和响应状态：

```bash
grep -i "Baiduspider" access.log \
  | awk '{print $7, $9}' \
  | sort | uniq -c | sort -nr | head -50
```

User-Agent 可以被伪造。如果需要确认访问者身份，应结合请求 IP，按百度公开说明进行反向 DNS 和正向 DNS 校验，而不是只看日志中的 `Baiduspider` 字样。

## 缩短重要页面的点击深度

蜘蛛主要通过链接发现页面。一个页面即使已经写入数据库，只要没有普通 HTML 链接指向它，就可能长期处于孤立状态。

建议让核心内容在较少点击内可达：

- 首页链接到主要栏目、专题或内容聚合页；
- 栏目页提供稳定的分页入口；
- 详情页加入相关内容、上下篇或同主题推荐；
- 对历史优质内容建立专题页或归档页；
- 面包屑导航链接到真实存在的上级栏目。

与其在每篇文章中随机加入大量链接，不如建立清晰的主题结构。例如：

```text
首页
├── SEO 教程
│   ├── 抓取与索引专题
│   │   ├── 日志分析文章
│   │   └── robots.txt 配置文章
│   └── 技术 SEO 专题
└── 建站教程
```

需要重点抓取的详情页，最好能从栏目页、专题页或相关文章中获得至少一个稳定入口。不要只依赖站内搜索结果，因为搜索结果页可能需要提交表单，且通常不适合作为稳定抓取路径。

分页也应提供普通 `<a>` 链接，而不是只能点击按钮后由 JavaScript 加载：

```html
<nav class="pagination">
  <a href="/news/page/2/">下一页</a>
</nav>
```

无限滚动可以保留给用户，但应同时提供蜘蛛可访问的分页 URL。

## 确保链接和正文无需复杂交互即可读取

百度具备一定的 JavaScript 处理能力，但渲染会增加抓取成本，也可能受到脚本报错、接口限制和加载超时影响。重要链接与主体内容更适合直接出现在服务器返回的 HTML 中。

以下写法对爬虫并不友好：

```html
<div onclick="location.href='/article/123'">查看文章</div>
```

应优先使用标准链接：

```html
<a href="/article/123">查看文章</a>
```

还要检查这些常见问题：

- 链接由登录后接口返回；
- 页面必须点击或滚动才加载正文；
- API 被 robots.txt 屏蔽，导致渲染不完整；
- 前端路由访问时返回空壳 HTML；
- 移动端页面缺少桌面端已有的内链；
- 链接使用临时签名，过期后无法访问。

如果采用前端框架，关键页面可以使用服务端渲染、静态生成或预渲染，使初始 HTML 中包含标题、正文和主要链接。

## 控制重复 URL，减少无效抓取

筛选、排序、跟踪参数和会话参数可能为同一内容生成大量 URL，例如：

```text
/product/100
/product/100?from=home
/product/100?sort=price
/product/100?session=abc
```

蜘蛛反复抓取这些地址，会挤占站内其他页面的抓取机会。可从以下方面处理：

1. 内链统一指向规范 URL，不在站内传播跟踪参数。
2. 同一内容只保留一个稳定、可返回 `200` 的主地址。
3. 旧地址永久迁移时使用 `301` 跳转到对应新地址。
4. 确实重复的页面可设置规范链接，作为 URL 归一化信号：

```html
<link rel="canonical" href="https://www.example.com/product/100">
```

5. 对没有搜索价值的组合筛选页，限制其生成数量和内链入口。

robots.txt 可以阻止特定路径被抓取，但它不等于删除索引，也不适合用于页面合并。如果已收录 URL 被直接禁止抓取，搜索引擎可能无法读取页面上的删除或规范化信号。

同时要避免把重要资源误封：

```text
User-agent: Baiduspider
Disallow: /private/
```

修改 robots.txt 后，应逐项核对目录匹配范围，尤其注意是否意外覆盖文章、分页、CSS、JavaScript 或渲染所需接口。

## 使用站点地图和资源提交补充发现入口

XML Sitemap 适合列出希望被发现和收录的规范 URL，特别是内链较深、更新频率较低的历史页面。基本格式如下：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://www.example.com/article/123</loc>
    <lastmod>2025-03-01</lastmod>
  </url>
</urlset>
```

Sitemap 中只应包含：

- 可公开访问的正式 URL；
- 返回正常状态的页面；
- 非跳转、非重复、非错误页面；
- 与站点首选协议和域名一致的地址。

不要把所有参数页、搜索结果页和已删除页面塞进 Sitemap。`lastmod` 应反映内容的实质更新时间，而不是每次生成文件时批量改成当天日期。

可以在百度搜索资源平台使用站点当前可用的 Sitemap 或资源提交方式。提交只能帮助发现 URL，不代表一定抓取、收录或获得排名，也不能替代内链建设。

## 改善服务器响应并持续复查日志

深层页面数量多时，服务器稳定性会直接影响抓取覆盖。重点检查：

- 是否频繁返回 `5xx`、连接超时或空白页面；
- `404` 页面是否错误返回 `200`，形成软 404；
- 是否存在多次连续跳转；
- CDN、防火墙或限流规则是否误拦蜘蛛；
- 页面首字节响应是否长期过慢；
- 不同终端或协议是否产生重复跳转。

状态码应与页面实际情况一致：

- 正常页面返回 `200`；
- 永久迁移使用 `301`；
- 已删除且无替代内容返回 `404` 或 `410`；
- 临时故障使用合适的 `5xx`，修复后恢复正常。

优化后不要只看某一天的数据。可按周统计百度蜘蛛抓取的有效页面数、状态码分布、参数 URL 占比，以及目标目录的抓取变化。如果蜘蛛仍主要消耗在重复页，应继续收紧参数入口；如果深层页面没有请求记录，则优先检查内链、分页和 Sitemap；如果已经抓取却长期没有索引，则应转向评估内容独特性、页面质量和规范化设置。

深层抓取优化本质上是建立一条完整路径：让重要 URL 容易被发现，让页面稳定返回可解析内容，并减少重复和错误地址对抓取资源的消耗。日志提供事实依据，内链决定发现效率，技术配置保证访问质量，三者应结合调整，而不是依赖一次提交或某个单独标签。
