# GitHub Pages如何提高搜索引擎收录

## 先确认站点具备被抓取的基本条件

搜索引擎收录 GitHub Pages 的前提，是爬虫能够稳定访问页面并识别有效内容。完成部署后，先检查以下项目：

1. 在无登录状态或浏览器隐私窗口中访问站点。
2. 确认首页和文章页返回正常内容，而不是 404、构建错误或空白页面。
3. 仓库的 Actions 或 Pages 部署记录中没有失败任务。
4. 页面源代码中不存在以下指令：

```html
<meta name="robots" content="noindex">
```

5. 页面不是只能通过 JavaScript 运行后才生成全部正文。GitHub Pages 常见的 Jekyll 静态页面通常没有这个问题，但部分单页应用需要额外关注搜索引擎渲染能力。

对于项目站点，默认地址通常是：

```text
https://用户名.github.io/仓库名/
```

此时内部资源和链接必须包含正确的子路径。如果页面引用 `/assets/style.css`，浏览器会请求域名根目录下的资源，而不是当前项目目录。Jekyll 站点应正确设置 `baseurl`，避免导航、图片和文章链接失效。

```yaml
url: "https://用户名.github.io"
baseurl: "/仓库名"
```

修改后应逐页测试链接，尤其是首页之外的文章、分类页和静态资源。

## 完善标题、描述与规范网址

每个可收录页面都应有独立、准确的 `<title>`。标题需要说明页面主题，不宜所有页面都只显示站点名称。文章页面可以采用“文章标题 - 站点名称”的形式。

页面还应提供自然的描述：

```html
<meta name="description" content="介绍 GitHub Pages 自定义域名、站点地图与搜索平台提交的具体配置方法。">
```

描述不直接保证排名，也不一定会被搜索结果原样采用，但有助于搜索引擎理解页面，并可能影响搜索摘要的呈现。

同一内容如果可以通过多个网址访问，还应设置 canonical，指出首选版本：

```html
<link rel="canonical" href="https://example.com/articles/github-pages-seo/">
```

这对启用自定义域名的站点尤其重要。配置域名后，应统一使用一个正式网址，不要在站内同时混用 `username.github.io`、自定义域名、HTTP 和 HTTPS 链接。

使用 Jekyll 时，可以在 `_config.yml` 中启用 GitHub Pages 支持的 `jekyll-seo-tag`：

```yaml
plugins:
  - jekyll-seo-tag
```

然后在页面布局的 `<head>` 中加入：

```liquid
{% seo %}
```

该插件可以根据站点配置和页面变量生成标题、描述、canonical 及部分社交分享标签。仍需检查 `_config.yml` 中的 `title`、`description`、`url` 和 `baseurl` 是否准确，插件不会自动修正错误配置。

## 生成并提交 sitemap.xml

站点地图可以帮助搜索引擎发现层级较深、缺少外链的新页面，但它只是发现机制，并不代表其中的网址一定会被收录。

Jekyll 项目可使用 `jekyll-sitemap`：

```yaml
plugins:
  - jekyll-sitemap
```

部署成功后，通常可以访问：

```text
https://example.com/sitemap.xml
```

项目站点则可能位于：

```text
https://用户名.github.io/仓库名/sitemap.xml
```

打开文件后应重点核对：

- URL 是否使用正式域名；
- 是否错误遗漏 `/仓库名/`；
- 是否包含测试页、重复页或无价值标签页；
- 列出的页面能否返回 HTTP 200；
- 是否混入旧域名或 HTTP 地址。

也可以手工维护 sitemap，但页面较多时容易遗漏。无论使用哪种方式，都不要在站点地图中提交 404、重定向目标错误或带有 `noindex` 的页面。

## 正确处理 robots.txt

`robots.txt` 用于控制爬虫访问范围，不是主动请求收录的工具。一个简单配置可以写成：

```text
User-agent: *
Allow: /

Sitemap: https://example.com/sitemap.xml
```

使用自定义域名或用户主页站点时，可将文件放在网站根目录，使其能够通过 `/robots.txt` 访问。

需要特别注意：如果站点地址是 `username.github.io/project/`，爬虫通常读取的是域名根目录下的：

```text
https://username.github.io/robots.txt
```

而不是项目仓库中的 `/project/robots.txt`。因此，单个项目仓库通常无法用子目录里的 robots 文件独立控制整个主机的抓取规则。

不要误写以下规则：

```text
User-agent: *
Disallow: /
```

它会阻止爬虫抓取整个适用范围。也不建议屏蔽 CSS、JavaScript 和图片目录，因为搜索引擎可能需要这些资源判断页面是否可用。需要阻止某个页面出现在搜索结果时，应优先使用 `noindex`，同时允许爬虫访问该页面以读取指令。

## 在搜索平台验证并请求抓取

仅等待爬虫自然发现新站点可能需要较长时间。站点上线后，可以在 Google Search Console 和 Bing Webmaster Tools 中添加网站。

验证方式可根据域名情况选择：

- 自定义域名：使用 DNS TXT 记录验证通常更稳定；
- `github.io` 地址：可以使用平台提供的 HTML 验证文件或 HTML 标签；
- 使用验证文件时，确认该文件部署后可直接访问，且内容未被模板修改。

验证完成后提交 sitemap 的实际地址，并使用 URL 检查工具查看重要页面。重点关注：

- 搜索引擎是否能抓取页面；
- 页面是否被 `noindex` 排除；
- canonical 是否指向其他网址；
- 抓取到的页面与浏览器看到的内容是否一致；
- 是否出现“已发现但尚未编入索引”或“已抓取但尚未编入索引”。

URL 检查中的“请求编入索引”适合用于少量新增或重要更新页面，不应当替代站内链接和站点地图，也不能保证最终收录。

## 用内容结构和内部链接提升可发现性

技术配置正确后，页面是否值得收录仍取决于内容本身。只有几句话、与其他页面高度重复，或仅罗列外部链接的页面，可能长期不被收录。

每篇文章应解决明确问题，并包含必要的操作步骤、代码示例、适用条件和常见错误。标题层级应保持清晰：页面只有一个主题标题，正文使用二级、三级标题组织内容，不要为了视觉效果跳跃使用标题标签。

同时建立可抓取的内部链接：

- 首页链接到主要栏目或核心文章；
- 栏目页链接到具体内容页；
- 相关文章之间使用描述性锚文本；
- 避免只有站内搜索框才能找到的孤立页面；
- 面包屑和上一篇、下一篇链接应使用普通 `<a href>`。

站外自然链接也能帮助爬虫发现网站。可以从个人主页、技术社区资料页或相关项目 README 链接到站点，但不应批量制造低质量链接。

## 收录异常时的排查顺序

如果页面长期未收录，可以按以下顺序检查：

1. 使用 `curl -I 页面网址` 查看状态码，目标页面应直接返回 200。
2. 检查是否存在重定向循环、404 或疑似软 404。
3. 查看源代码中的 robots 和 canonical 标签。
4. 检查 sitemap 中的网址是否与正式域名一致。
5. 确认页面能从首页或栏目页通过普通链接到达。
6. 在搜索平台查看抓取时间、索引状态和具体原因。
7. 比较页面与站内其他内容，判断是否过短、重复或缺少独立价值。
8. 修改后等待重新抓取，不要反复更换 URL。

GitHub Pages 本身并不会妨碍搜索引擎收录。更关键的是保持网址稳定、部署可访问、元数据准确、站点地图有效，并持续提供可被内部链接发现的原创内容。完成这些基础工作后，再根据搜索平台报告逐项修复，比频繁提交网址或添加大量关键词更有效。
