# Nofollow属性SEO使用与优化方法

{% raw %}

`nofollow` 是链接关系属性，用于告诉搜索引擎：网站不希望为该链接提供常规的推荐或背书信号。它常见于广告链接、用户发布的内容以及无法确认可信度的外部链接。

合理使用 `nofollow` 有助于降低不自然链接、垃圾内容和付费链接带来的风险，但它不是阻止抓取、禁止收录或提升排名的万能工具。优化时应先判断链接的性质，而不是给所有外链统一添加该属性。

## Nofollow 属性有什么作用

标准写法如下：

```html
<a href="https://example.com" rel="nofollow">示例链接</a>
```

`rel` 用于描述当前页面与目标页面的关系。添加 `nofollow` 后，搜索引擎通常不会把该链接视为站点对目标页面的正常推荐。

需要注意，Google 已将 `nofollow` 以及后续推出的 `sponsored`、`ugc` 视为判断链接性质的“提示”，而不是在所有场景下都必须遵守的绝对指令。其他搜索引擎的处理方式也可能不同，因此不能把它理解为“搜索引擎一定不会访问这个链接”。

它主要影响链接信号的解释，不等同于以下功能：

- **不是禁止抓取**：搜索引擎仍可能通过其他页面、站点地图或历史记录发现目标网址。
- **不是禁止收录**：目标页面是否收录取决于页面自身状态以及搜索引擎的判断。
- **不是隐藏链接**：用户和爬虫都能在 HTML 中看到链接。
- **不是安全隔离措施**：恶意网址、开放跳转和用户输入仍需通过程序进行验证。

如果目标是阻止某个页面出现在搜索结果中，应在允许抓取的前提下使用 `noindex`，而不是依赖指向该页面的 `nofollow`。

## Nofollow、Sponsored 与 UGC 如何选择

现代链接标记不只有 `nofollow`。应根据链接产生的原因选择更准确的属性。

### 付费、广告和赞助链接

因广告费、赞助、商品赠送或其他商业合作而产生的链接，优先使用：

```html
<a href="https://advertiser.example" rel="sponsored">赞助商网站</a>
```

也可以组合使用：

```html
<a href="https://advertiser.example" rel="sponsored nofollow">
  赞助商网站
</a>
```

`sponsored` 能更明确地表达商业关系。对于过去已经使用 `nofollow` 标记的付费链接，通常不必为了形式统一而大规模改写，但新链接建议采用更具体的属性。

### 用户生成内容中的链接

论坛帖子、评论、问答和用户主页中的外链可以使用：

```html
<a href="https://user-site.example" rel="ugc">用户提交的网站</a>
```

`ugc` 是 User Generated Content 的缩写。若网站无法审核用户链接，也可以写成：

```html
<a href="https://user-site.example" rel="ugc nofollow">用户链接</a>
```

### 无法确认可信度的普通外链

编辑暂时无法确认目标页面质量，或不愿对其进行推荐时，可以使用 `nofollow`。但正常引用的权威资料、官方文档和可靠来源，没有必要一律添加该属性。

## 哪些场景应该使用 Nofollow

实际优化中，可按以下规则判断：

1. **存在付费关系**
   广告、联盟营销、软文合作和赞助链接应标明商业属性。联盟链接即使经过跳转，也不代表可以省略相关标记。

2. **链接由用户自行发布**
   未经过编辑审核的评论、论坛签名和个人资料链接，适合使用 `ugc` 或 `ugc nofollow`，同时配合反垃圾机制。

3. **网站不愿为目标内容背书**
   例如，为说明问题而引用低质量页面、争议页面或垃圾案例时，可以添加 `nofollow`。

4. **第三方组件自动插入链接**
   小工具、徽章、模板或插件可能附带外链。站长应检查其用途；不具备编辑推荐意义的链接，可删除或设置适当的 `rel` 属性。

以下情况则不建议机械使用：

- 给全部外部链接添加 `nofollow`；
- 给所有站内链接添加 `nofollow`；
- 用它代替用户权限、登录控制或内容审核；
- 试图通过大量站内 `nofollow` 集中页面权重；
- 用它处理重复内容、分页或规范网址问题。

自然、可验证的外部引用有助于读者理解内容。是否使用属性，应由链接关系决定，而不是简单区分“站内”和“站外”。

## 正确配置代码与技术细节

一个链接可以包含多个 `rel` 值，各值之间使用空格分隔：

```html
<a
  href="https://example.com/product"
  rel="sponsored nofollow"
  target="_blank"
>
  查看合作产品
</a>
```

`target="_blank"` 与 `nofollow` 没有直接关系。前者控制打开方式，后者描述链接关系。现代浏览器通常会为新窗口链接提供一定的安全保护，但如需兼容旧环境，可以明确加入：

```html
rel="noopener noreferrer sponsored"
```

其中，`noopener` 主要用于防止新页面通过 `window.opener` 控制来源页面，不能替代 `nofollow` 或 `sponsored`。

批量生成页面时，应在模板层处理属性，而不是发布后逐条修改。例如，评论模板可以输出：

```html
<a href="{{ user_url }}" rel="ugc nofollow">
  {{ user_name }}
</a>
```

模板变量必须经过 URL 校验和 HTML 转义。`nofollow` 无法防止 `javascript:` 协议、恶意跳转或跨站脚本攻击。

对于 GitHub Pages 等静态网站，可以直接在 Markdown 中嵌入 HTML：

```html
<a href="https://partner.example" rel="sponsored nofollow">合作链接</a>
```

普通 Markdown 链接语法通常不能直接设置 `rel`，具体还取决于所用 Markdown 渲染器和主题模板。GitHub Pages 本身不会自动判断某个链接是否应标记为广告或用户内容，站长需要在文章 HTML、布局文件或生成逻辑中配置。

## 站内链接不要依赖 Nofollow 塑形

过去有人通过给部分站内链接添加 `nofollow`，尝试把更多链接权重集中到指定页面。这种“权重雕刻”并不是可靠的优化方法，也可能妨碍搜索引擎理解网站结构。

对于不重要或不希望公开索引的页面，应按真实目标处理：

- 登录、购物车等功能入口：保留正常可用性，按需要配置抓取和索引策略；
- 重复页面：使用规范链接、重定向或统一 URL 参数；
- 不应出现在搜索结果中的页面：使用 `noindex`，并确保爬虫能够读取该指令；
- 已永久迁移的页面：使用服务器端 `301` 或 `308` 重定向；
- 孤立页面：通过合理的栏目、面包屑和正文链接建立结构。

如果给重要栏目、文章详情页或分页入口添加 `nofollow`，可能削弱搜索引擎发现深层页面和理解内容关系的能力。站内链接优化的重点应是清晰导航、准确锚文本和合理层级。

## 如何审计和优化 Nofollow 链接

可以按月度或季度执行一次链接审计：

1. **抓取全站链接**
   使用网站爬虫或导出页面 HTML，整理来源网址、目标网址、锚文本和 `rel` 属性。

2. **按链接关系分类**
   区分编辑推荐、广告合作、联盟链接、用户内容、站内导航和无法确认来源的链接。

3. **检查错误标记**
   重点查找重要站内链接被误设为 `nofollow`、广告链接未标记、属性拼写错误以及模板重复输出等问题。

4. **检查目标状态**
   即使链接带有 `nofollow`，也应处理失效页面、跳转链、HTTPS 混用和可疑域名，以免影响用户体验。

5. **验证最终 HTML**
   不要只检查编辑器中的源码。JavaScript、主题或插件可能在渲染后修改属性，应以浏览器开发者工具或抓取结果为准。

6. **保留修改记录**
   记录修改原因、页面范围和日期，后续结合抓取数据、索引情况与用户点击表现观察变化。

`nofollow` 的核心价值是准确说明链接关系。广告使用 `sponsored`，用户内容使用 `ugc`，普通不背书链接使用 `nofollow`；需要控制收录或迁移网址时，则应采用对应的索引与重定向方案。清晰分类、正确输出并定期审计，比全站批量添加属性更符合长期 SEO 和用户体验需求。
