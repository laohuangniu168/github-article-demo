# 百度SEO抓取资源优化实战指南

{% raw %}

百度蜘蛛能够访问多少页面，通常会受到网站规模、更新频率、服务器稳定性、页面质量和历史抓取情况等因素影响。优化抓取资源的重点，不是单纯追求更高频次，而是减少重复、无效和高成本请求，让有限访问更多落到可索引的重要页面上。

## 先判断抓取资源浪费在哪里

开始调整前，应先建立可验证的基线。百度搜索资源平台可以帮助了解抓取异常、索引量和链接提交情况，但更细致的诊断仍要依靠服务器访问日志。

筛选日志中 User-Agent 包含 `Baiduspider` 的请求，至少统计以下数据：

- 每日抓取次数及变化趋势；
- 返回 200、301、302、404、5xx 的比例；
- 抓取最多的 URL、目录和参数组合；
- HTML、图片、接口、静态资源分别占多少请求；
- 平均响应时间及慢请求页面；
- 重要页面多久被重新抓取一次。

例如可在 Nginx 日志中快速查看相关请求：

```bash
grep -i "Baiduspider" access.log | awk '{print $7}' \
  | sort | uniq -c | sort -nr | head -50
```

User-Agent 可以被伪造，因此日志中的身份信息不能用于安全判断。若需要更严谨地识别爬虫，可结合来源 IP 的反向 DNS 和正向解析进行核验，而不是仅凭请求头放行或限流。

诊断时可以计算一个简单指标：

> 有效抓取率 = 返回 200 且具备索引价值的 HTML 请求数 ÷ 百度蜘蛛总请求数

如果大量请求落在筛选参数、失效链接、重定向链或空内容页面上，就有明确的优化空间。

## 收敛重复 URL 和无限参数空间

抓取浪费最常见的原因，是同一内容可以通过多个地址访问。例如：

```text
/product/123
/product/123?from=nav
/product/123?utm_source=test
/product/123?sort=default
```

搜索引擎可能把这些地址当作不同 URL 发现并访问。处理时应从网站生成机制入手，而不是只依赖搜索引擎自行判断。

建议按以下顺序治理：

1. **统一站内链接**：导航、面包屑、相关推荐和分页只链接规范 URL。
2. **删除无业务价值的参数**：统计参数尽量通过前端或分析工具处理，不要持续生成可抓取链接。
3. **设置规范地址**：重复页面可添加 `rel="canonical"` 指向主版本，但 canonical 通常属于规范化提示，不应作为唯一手段。
4. **永久迁移使用 301**：域名、协议或路径发生长期变更时，旧地址直接跳转到最终地址。
5. **控制组合筛选**：颜色、价格、地区、排序等条件叠加后可能产生近乎无限的 URL，应只开放有独立搜索价值的组合。

`robots.txt` 可用于阻止明确不希望被抓取的目录或参数模式，例如后台、内部搜索结果页：

```txt
User-agent: Baiduspider
Disallow: /admin/
Disallow: /search?
Disallow: /*?sessionid=
```

规则上线前要确认不会误封正文、CSS、JavaScript或图片资源。还要注意，robots 禁止抓取并不等于删除已收录 URL；对于已经存在于索引中的失效页面，应同时正确返回状态码，并按需使用百度搜索资源平台提供的死链相关能力。

## 用正确状态码减少重复消耗

状态码会直接影响爬虫后续如何处理 URL。网站常见的问题不是错误页太多，而是错误页仍然返回 `200 OK`。

### 404 与 410

不存在且没有替代内容的地址，应返回 404；明确永久删除的资源也可根据实际情况返回 410。不要把所有失效页面都跳转到首页，这会让搜索引擎难以判断原页面是否真正消失，还可能形成软 404。

### 301 与重定向链

永久变更使用 301，并尽量一步到达最终页面：

```text
错误：A → 301 → B → 302 → C
推荐：A → 301 → C
```

应重点检查 HTTP 到 HTTPS、带不带 `www`、末尾斜杠和大小写规则，避免不同规范化逻辑互相跳转。

### 5xx 与限流

持续出现 500、502、503 或超时，可能降低抓取稳定性。发布、维护或临时过载时，应优先修复服务能力，不要把百度蜘蛛长期统一拦截为 403。

如确需临时限流，可结合缓存、请求速率和服务器负载做温和控制。对于短时维护，503 比返回一个内容错误但状态为 200 的“维护页面”更准确；如使用 `Retry-After`，也应确保恢复时间合理。

## 降低重要页面的抓取成本

抓取资源优化也包括服务器侧成本。若 HTML 页面经常需要数秒才能生成，搜索引擎在同一时间内能够完成的请求自然更少。

可采取的措施包括：

- 为栏目页、文章页和商品详情页增加页面缓存；
- 优化慢 SQL，避免每次访问执行大量关联查询；
- 开启 Gzip 或 Brotli，但确保不同客户端兼容；
- 使用 CDN 承载图片、CSS 和 JavaScript，并保持资源 URL 稳定；
- 设置合理的 `Last-Modified` 或 `ETag`，支持条件请求；
- 不要频繁改变页面模板中的无意义内容和时间戳；
- 确保移动端与桌面端的核心内容可稳定访问。

对依赖 JavaScript 才能出现正文的网站，应检查初始 HTML 是否包含标题、主体内容和关键链接。搜索引擎具备一定的页面渲染能力，但渲染通常比直接解析 HTML 成本更高，也可能受到脚本报错、接口权限或加载超时影响。重要内容采用服务端渲染或静态生成通常更稳妥。

## 改善重要 URL 的发现路径

减少浪费后，还要让新增和更新页面更容易被发现。首先应建立清晰的站内链接结构，使重要页面无需经过过多点击即可到达。

XML Sitemap 适合提供规范、可访问的 URL 清单。文件中只应包含：

- 返回 200 的正式页面；
- 允许抓取的 URL；
- 站内采用的规范版本；
- 确实有索引价值的内容。

`lastmod` 应反映页面主体内容的实际更新时间，而不是每次请求都改成当前日期。错误更新时间会增加不必要的重新检查，也会削弱该字段的参考价值。

对于新增或发生实质更新的页面，可以通过百度搜索资源平台当前提供的链接提交方式进行提交。提交的作用是帮助搜索引擎发现 URL，不代表一定抓取、收录或获得排名。不要反复提交未变化页面，也不要提交重定向、404、被 robots 禁止或质量不足的地址。

## 建立可复查的优化闭环

抓取治理应分批实施，避免一次修改 robots、重定向、导航和参数规则后无法判断影响来源。每轮调整可以按以下流程执行：

1. 保存调整前 14～30 天的日志、抓取异常和索引数据；
2. 找出请求量最高的无效 URL 类型；
3. 优先从链接源头、状态码和规范化规则解决；
4. 小范围上线并检查 robots 与重定向结果；
5. 持续观察百度蜘蛛请求分布和服务器错误；
6. 比较重要页面抓取间隔、有效抓取率及索引变化。

需要避免只看“抓取次数”这一项。总次数下降并不一定是坏事：如果参数页、错误页和重定向请求明显减少，而核心内容抓取保持稳定，有效利用率反而可能提高。相反，抓取量上升也可能只是网站制造了更多重复 URL。

真正有价值的优化结果，是URL空间更可控、服务器响应更稳定、状态码更准确，并且新内容能够通过站内链接、Sitemap和合适的提交渠道被持续发现。排名与收录仍会受到内容质量、需求匹配和站点整体信号等多方面影响，抓取优化解决的是技术入口问题，而不是结果保证。
