# 静态网站内容结构优化方法

## 先建立可扩展的内容分类

静态网站没有数据库并不意味着内容可以随意堆放。目录、导航和页面关系一旦混乱，后期增加文章时容易出现重复主题、孤立页面和路径频繁变更等问题。

规划结构前，先整理三类信息：

1. **核心主题**：网站长期覆盖的主要领域，适合作为一级栏目。
2. **细分主题**：用户会持续查询的具体问题，可作为二级栏目或专题页。
3. **单篇内容**：解决一个明确需求的文章、文档或案例。

例如，一个前端教程站可以采用以下结构：

```text
/
├── html/
│   ├── semantic-tags/
│   └── forms/
├── css/
│   ├── layout/
│   └── responsive-design/
├── javascript/
│   ├── basics/
│   └── async/
└── tools/
    ├── git/
    └── vscode/
```

栏目数量不宜只追求多。若某个栏目长期只有一篇内容，可以暂时并入更上层的分类。反过来，当一个目录下积累了大量不同主题的页面，也应拆分子栏目，避免用户只能依靠搜索找到内容。

分类时应以用户理解方式为主，而不是完全照搬内部组织名称。例如，与其使用“技术中心一部”，不如使用“部署指南”或“性能优化”等能够说明内容范围的名称。

## 设计稳定且可读的 URL

静态页面的文件路径通常直接影响 URL，因此目录命名需要在发布前确定。一个理想的 URL 应简短、稳定，并能让用户大致判断页面内容。

推荐形式：

```text
https://example.com/seo/site-structure/
https://example.com/github-pages/custom-domain/
```

应注意以下几点：

- 使用小写字母，单词之间用连字符分隔。
- 避免在路径中加入无实际意义的编号，如 `/article/00125/`。
- 日期只适合新闻、日志等强时效内容，常青教程不必加入年月。
- 不要因标题小幅修改而频繁更换 URL。
- 同一站点统一采用带或不带尾部斜杠的形式。
- 文件名和目录名尽量使用 ASCII 字符，减少编码和迁移问题。

如果必须调整已有路径，应配置永久重定向，并同步更新站内链接与站点地图。但 GitHub Pages 本身不提供通用的服务器端重定向规则，不能直接配置 Nginx 或 Apache 的 301。使用 GitHub Pages 时，应尽量保持旧路径；若采用 Jekyll，可借助兼容插件生成跳转页面，但这类客户端或 HTML 跳转并不完全等同于服务器端 301。

## 用页面层级表达内容关系

清晰的页面结构既方便阅读，也有助于搜索引擎理解正文重点。每个页面应围绕一个主要意图展开，不要把多个缺乏关联的问题强行拼在一起。

页面正文可按以下层次组织：

- 页面主标题：概括当前页面的核心主题。
- 二级标题：对应主要步骤、问题或内容模块。
- 三级标题：解释二级标题下的具体分支。
- 列表、表格和代码块：承载适合结构化展示的信息。

HTML 中应尽量使用语义化元素：

```html
<header>站点标题与主要导航</header>

<nav aria-label="面包屑导航">
  <a href="/">首页</a> /
  <a href="/seo/">SEO</a> /
  <span>内容结构</span>
</nav>

<main>
  <article>
    <h1>页面主标题</h1>
    <h2>主要章节</h2>
    <p>正文内容</p>
  </article>
</main>

<footer>版权与辅助链接</footer>
```

每个页面通常保留一个清晰的主标题即可。不要仅为了放大字体而使用标题标签，也不要从二级标题直接跳到四级标题。视觉效果应交给 CSS，标题标签负责表达层级。

分类页也不应只是链接集合。可以加入栏目简介、适用人群、内容分组和推荐阅读，使其真正承担主题入口的作用。

## 通过内链连接栏目、专题与文章

静态网站最常见的问题之一是孤立页面：文件已经发布，但导航、栏目页和相关文章都没有入口。搜索引擎可能通过站点地图发现页面，用户却很难从站内访问它。

可以建立三层内链体系：

### 全站导航

主导航只保留最重要的栏目，避免把所有页面都塞进菜单。页脚可放置关于网站、联系方式、隐私说明等辅助入口。

### 面包屑导航

面包屑展示当前页面在站点中的位置，例如：

```text
首页 > 部署指南 > GitHub Pages > 自定义域名
```

其中上级栏目应可以点击，当前页面通常不必重复链接自身。若添加结构化数据，应按照 Google 支持的 `BreadcrumbList` 格式编写，并使用相关测试工具检查语法；正确标记不代表搜索结果一定会展示面包屑样式。

### 上下文链接

正文中提到前置知识、相关概念或后续步骤时，可自然链接到对应页面。锚文本应说明目标内容，例如“配置 canonical 地址”通常比“点击这里”更明确。

每篇新内容发布前，至少检查：

- 是否有栏目页指向它；
- 是否能链接到必要的上级或基础内容；
- 是否存在两到三篇相关旧内容可以增加入口；
- 链接是否使用最终 URL，而非构建前的本地文件路径。

## 统一模板，同时减少重复信息

静态站通常通过 Jekyll、Hugo、Eleventy、Astro 等工具复用布局。模板统一能降低维护成本，但也容易让大量页面出现相同标题、描述或无意义文本。

模板中应区分全站固定内容与页面独立内容：

```html
<title>页面标题 - 站点名称</title>
<meta name="description" content="当前页面的独立摘要">
<link rel="canonical" href="https://example.com/seo/site-structure/">
```

页面标题应准确描述内容，避免所有页面只显示站点名称。description 用于概括页面价值，可以影响搜索结果摘要的候选内容，但搜索引擎可能根据查询改写展示文本。

还需控制以下重复来源：

- 标签页、分类页和归档页生成大量相似列表；
- 同一内容同时存在 `.html`、目录形式或不同参数版本；
- 打印页、旧版本和正文页内容高度一致；
- 模板在正文前加入过长的固定介绍。

canonical 用于提示首选 URL，但不是强制指令。更稳妥的做法是统一站内链接、站点地图和实际访问地址，避免依赖 canonical 修复所有重复问题。

## 配置抓取入口并持续检查

内容结构完成后，还应让机器能够稳定访问。静态网站至少需要检查 `robots.txt`、XML 站点地图、错误页面和 HTTPS 地址是否一致。

简单的 `robots.txt` 可以写成：

```text
User-agent: *
Allow: /

Sitemap: https://example.com/sitemap.xml
```

不要误把需要收录的 CSS、JavaScript 或图片目录屏蔽掉。`robots.txt` 也不是隐藏敏感文件的安全措施，真正不应公开的内容不应部署到公开站点。

站点地图应只提交规范、可访问且希望被索引的 URL。它能帮助搜索引擎发现页面，但不能保证收录。GitHub Pages 若使用受支持的 Jekyll 配置，可以通过插件生成 sitemap；使用其他静态生成器时，则应在构建阶段生成并部署对应文件。

上线后可定期进行以下检查：

1. 使用爬虫工具查找 404、重定向链和孤立页面。
2. 在 Google Search Console 等平台查看抓取与索引反馈。
3. 检查重要页面从首页或栏目页需要多少次点击才能到达。
4. 合并主题重复、长期缺乏独立价值的页面。
5. 更新旧文章时保留稳定 URL，并修复失效外链和站内链接。

良好的静态网站结构不是一次性的目录整理，而是一套持续维护规则：先确定主题边界，再用稳定路径、语义层级和内链表达关系，最后通过构建检查与抓取数据发现问题。这样既能降低内容扩展成本，也能让用户和搜索引擎更准确地理解每个页面的作用。
