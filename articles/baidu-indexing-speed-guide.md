# 百度网站页面快速收录优化方法

{% raw %}

## 先判断页面为什么没有被收录

百度页面进入搜索结果，通常要经过“发现 URL—抓取页面—解析内容—建立索引”几个阶段。提交链接只能帮助搜索引擎发现页面，不能代替内容审核，也不能保证最终收录。

优化前应先确认问题发生在哪一步：

1. 在百度搜索中查询完整 URL，检查页面是否已经被索引。
2. 使用 `site:域名` 粗略了解站点收录情况，但不要把结果数量视为精确统计。
3. 登录百度搜索资源平台，查看索引量、抓取频次、抓取异常等数据。
4. 检查服务器访问日志，确认是否出现百度蜘蛛访问记录。
5. 使用平台提供的抓取诊断工具，查看页面能否正常访问和解析。

如果日志中一直没有抓取记录，重点解决链接发现和抓取权限；如果已经抓取但长期未收录，则应优先检查页面质量、重复内容和技术状态。

## 确保百度蜘蛛可以稳定抓取

页面能被普通浏览器打开，不代表搜索引擎也能正常抓取。以下技术问题会直接影响收录效率。

### 正确配置 robots.txt

不要误封需要收录的目录。基础配置可以写成：

```txt
User-agent: *
Disallow:

Sitemap: https://www.example.com/sitemap.xml
```

上线前应重点排查以下规则：

```txt
Disallow: /
Disallow: /article/
Disallow: /*.html
```

这些规则可能阻止全站、文章目录或 HTML 页面被抓取。修改后还要检查页面源代码中是否存在：

```html
<meta name="robots" content="noindex">
```

`noindex` 表示不希望页面进入索引，不应出现在需要收录的正式内容页中。

### 统一 URL 和状态码

同一内容如果同时存在 HTTP、HTTPS、带 `www`、不带 `www`、不同参数等多个地址，会分散抓取资源。建议确定唯一版本，并通过 301 重定向统一入口。

页面状态码也要准确：

- 正常内容返回 `200`
- 永久更换地址返回 `301`
- 已删除且无替代内容返回 `404` 或 `410`
- 不要让错误页面返回 `200`

分页、筛选参数和重复页面较多时，可合理使用 canonical：

```html
<link rel="canonical" href="https://www.example.com/article/123.html">
```

canonical 是规范化提示，不是强制指令，目标地址必须可访问且内容具有对应关系。

### 改善可访问性与渲染方式

服务器频繁超时、DNS 不稳定或大量返回 `5xx`，会降低抓取效率。应压缩图片、启用缓存、减少无必要的重定向，并确保百度蜘蛛不会被防火墙、CDN 规则或验证码拦截。

对于依赖 JavaScript 才能显示正文的单页应用，建议使用服务端渲染、静态生成或预渲染，让初始 HTML 中直接包含标题和主要内容。不要只返回一个空容器，再完全依赖浏览器执行脚本。

## 提高新页面本身的收录价值

技术配置正常后，页面是否值得建立索引，取决于它能否提供独立、清晰且可验证的信息。

一篇更容易被理解的页面通常具备以下特征：

- 标题准确说明页面解决的问题，不夸张，也不堆砌近义词。
- 正文直接回应搜索需求，包含步骤、条件、示例和注意事项。
- 内容具有独立价值，而不是批量替换地区、产品名生成的模板页。
- 页面主题集中，标题、正文、图片说明和内部链接语义一致。
- 标注作者、更新时间、来源或适用范围，增强信息透明度。
- 删除大段重复导航、采集内容和与正文无关的广告模块。

新站尤其不适合一次发布大量低差异页面。例如，为每个城市生成一篇结构完全相同的文章，即使 URL 不同，也可能被判断为重复或低价值内容。

更新时间也应真实。只有修正数据、补充案例或调整方法时才更新日期，单纯修改时间通常不能带来有效的重新评估。

## 使用百度官方渠道提交新链接

完成百度搜索资源平台的站点验证后，可以根据后台实际开放的功能提交 URL。不同站点能够使用的入口和配额可能不同，应以平台当前页面及官方文档为准。

### 提交 Sitemap

Sitemap 适合帮助百度持续发现站内 URL。示例：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://www.example.com/article/123.html</loc>
    <lastmod>2025-03-01</lastmod>
  </url>
</urlset>
```

注意事项：

- Sitemap 中只放可访问、允许收录的规范 URL。
- `lastmod` 应反映内容真实修改时间。
- 不要提交 404、跳转页、搜索结果页和大量参数页。
- 文件较大时应拆分，并通过 Sitemap 索引文件管理。

### 通过 API 推送新增 URL

如果百度搜索资源平台为站点提供普通收录 API，可在内容发布后自动推送。常见调用形式如下，实际地址和参数应从站点后台复制：

```bash
curl -H 'Content-Type:text/plain' \
  --data-binary @urls.txt \
  'http://data.zz.baidu.com/urls?site=https://www.example.com&token=你的令牌'
```

`urls.txt` 每行放一个完整地址：

```txt
https://www.example.com/article/123.html
https://www.example.com/article/124.html
```

令牌属于敏感信息，不应写入公开仓库或前端代码。程序还要记录接口返回结果，避免重复推送和超过配额。

所谓“快速收录”并非所有站点都默认拥有，资格、配额和使用条件可能调整。即使提交成功，也只代表百度收到链接，不等于已经抓取或收录。

## 用站内链接缩短页面发现路径

只依赖 Sitemap 或接口并不理想。新页面还应进入正常的网站结构，让搜索引擎和用户都能找到。

可执行的做法包括：

1. 在栏目页、专题页或最新内容区添加入口。
2. 从已有收录且主题相关的文章中添加自然内链。
3. 保持面包屑导航清晰，避免产生死循环。
4. 重要页面尽量不要距离首页过深。
5. 定期检查孤立页面，即没有任何站内链接指向的 URL。
6. 为列表分页提供可抓取的普通链接，不要只依赖点击事件加载。

内链锚文本应描述目标内容，例如“查看 robots.txt 配置方法”比“点击这里”更容易表达页面关系。但不要在每篇文章中机械加入大量相同锚文本。

外部链接也可能帮助百度发现页面，但应以真实引用和正常传播为前提。购买批量链接、制造垃圾页面或频繁提交到低质量目录，可能带来风险，并不能稳定解决收录问题。

## 根据抓取数据持续排查

提交页面后不要反复改 URL 或高频重复推送。可以按“发布—提交—观察—修正”的顺序管理：

- 发布后检查状态码、canonical、robots 和正文源代码。
- 将 URL 加入 Sitemap，并按平台权限进行主动提交。
- 观察服务器日志中百度蜘蛛的访问时间与响应状态。
- 在搜索资源平台查看抓取异常和索引趋势。
- 对已抓取但长期未收录的页面，检查是否重复、过薄或缺少独立价值。
- 对大量未抓取页面，检查站点结构、服务器稳定性和抓取阻挡规则。

不要用当天是否收录作为唯一判断标准。不同站点的抓取频次、信任积累和内容规模不同，处理时间也会不同。真正有效的优化，是让 URL 容易被发现、页面能够稳定抓取、内容值得建立索引，并通过官方数据和日志持续验证。
