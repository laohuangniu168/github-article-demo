# SEO网站图片优化完整指南

{% raw %}

图片优化不只是压缩文件。搜索引擎需要理解图片内容和所在页面，用户则希望图片清晰、加载迅速且不会造成页面跳动。有效的优化应同时兼顾可访问性、页面性能、图片可发现性与维护成本。

## 选择合适的格式与尺寸

图片格式应根据内容类型选择，而不是全站统一转换。

- **JPEG**：适合照片、渐变和色彩丰富的图片，兼容性好，但不支持透明背景。
- **PNG**：适合需要透明背景的图标、截图和线条图，文件通常较大。
- **WebP**：同时支持有损、无损和透明效果，通常比 JPEG、PNG 更节省体积。
- **AVIF**：压缩效率较高，适合大图，但编码速度和部分旧环境兼容性需要评估。
- **SVG**：适合 Logo、图标和简单矢量图，不适合复杂照片。使用外部来源的 SVG 时，应注意其中可能包含脚本或恶意代码。

不要上传一张 4000 像素宽的原图，再用 CSS 将其缩小到 800 像素。应根据页面实际显示宽度生成多个版本。例如，正文区域最大宽度为 900 像素时，可以准备 480、800、1200 像素三个规格，兼顾不同设备和高像素密度屏幕。

压缩时应在画质与体积之间取平衡。产品细节图可以保留较高质量，装饰性背景则可以更激进地压缩。建议用 Lighthouse、PageSpeed Insights 或浏览器 Network 面板检查实际传输体积，而不是只看本地文件大小。

## 规范文件名、URL 与图片周边内容

图片文件名可以向搜索引擎提供基础语义。相比 `IMG_4837.jpg`，`black-running-shoes-side-view.webp` 更容易理解。文件名应简短、准确，并使用连字符分隔单词。

中文文件名虽然可以使用，但经过 URL 编码后不便于复制、排查和迁移。对于需要长期维护的网站，通常更适合使用小写英文、数字和连字符。

还应注意以下问题：

1. 图片 URL 尽量保持稳定，避免每次构建都无必要地更换地址。
2. 不要把所有图片命名成近似的关键词组合。
3. 图片所在页面应有明确主题，正文、标题和图注应与图片内容相关。
4. 重要图片附近可以添加自然的说明文字，帮助用户理解图片用途。
5. 同一图片如果出现在多个页面，应避免为了制造“唯一性”而生成大量无意义副本。

搜索引擎对图片的理解不仅来自文件名，也来自替代文本、页面正文、图注、链接关系和整体主题。单独修改文件名通常不会产生明显效果。

## 正确编写 alt 替代文本

`alt` 属性首先服务于无法看到图片的用户，包括使用屏幕阅读器的人；同时也能帮助搜索引擎理解图片。好的替代文本应描述图片在当前页面中的作用，而不是罗列关键词。

```html
<img
  src="/images/coffee-grinder-settings.webp"
  alt="手摇咖啡磨豆机的粗细刻度调节环"
  width="800"
  height="533"
>
```

不同类型图片应采用不同写法：

- **内容图片**：描述其中与正文有关的信息。
- **功能图片**：描述操作目的，例如搜索按钮图标可写“搜索”。
- **装饰图片**：使用空属性 `alt=""`，让屏幕阅读器忽略它。
- **图表或信息图**：简要说明核心结论，并在正文中提供完整数据或文字解释。
- **作为链接的图片**：替代文本应表达链接目标或操作目的。

不建议写成“图片”“产品图片”，也不要重复附近已经出现的完整句子。例如鞋类页面中的产品图，可以写“黑色越野跑鞋外侧面”，没必要写“跑鞋、运动鞋、男鞋、户外鞋购买”。

如果图片加载失败，替代文本也能保留必要信息。因此，即使某张图不以获取图片搜索流量为目标，也值得正确处理。

## 使用响应式图片并控制页面布局

移动端与桌面端不应强制下载同一张超大图片。可以使用 `srcset` 和 `sizes`，让浏览器根据视口与布局选择合适资源：

```html
<img
  src="/images/desk-800.webp"
  srcset="
    /images/desk-480.webp 480w,
    /images/desk-800.webp 800w,
    /images/desk-1200.webp 1200w
  "
  sizes="(max-width: 600px) 100vw, 800px"
  alt="靠窗摆放的木质办公桌"
  width="1200"
  height="800"
>
```

`srcset` 中的宽度必须与文件实际宽度一致，`sizes` 则应反映图片在页面中的真实显示宽度。配置错误可能导致浏览器仍然下载过大的文件。

为图片设置 `width` 和 `height` 属性，可以让浏览器提前计算宽高比，减少加载过程中内容位移，对改善 CLS 有帮助。响应式 CSS 可以这样写：

```css
img {
  max-width: 100%;
  height: auto;
}
```

如果需要根据浏览器能力或屏幕尺寸切换格式与构图，可以使用 `<picture>`：

```html
<picture>
  <source srcset="/images/banner.avif" type="image/avif">
  <source srcset="/images/banner.webp" type="image/webp">
  <img
    src="/images/banner.jpg"
    alt="设计团队在会议室讨论网站原型"
    width="1200"
    height="675"
  >
</picture>
```

其中 `<img>` 是必要的回退内容，也承载替代文本。

## 优化加载顺序与核心性能指标

首屏主图经常是页面的最大内容元素，可能影响 LCP。此类图片不应默认延迟加载，可以适度提高获取优先级：

```html
<img
  src="/images/hero.webp"
  alt="春季徒步路线经过山谷与湖泊"
  width="1440"
  height="810"
  fetchpriority="high"
>
```

`fetchpriority="high"` 只应给很可能成为 LCP 的关键图片使用，不要同时加在多张图片上。必要时可以预加载关键图片，但过度预加载会争抢带宽，反而拖慢 CSS、字体等资源。

首屏以下图片可以使用浏览器原生懒加载：

```html
<img
  src="/images/trail-map.webp"
  alt="徒步路线与补给点地图"
  width="900"
  height="600"
  loading="lazy"
  decoding="async"
>
```

为了便于抓取，重要图片应保留真实的 `src` 或 `srcset`。只把地址放进 `data-src`，再完全依赖 JavaScript 替换，可能增加渲染和抓取的不确定性。CSS 背景图适合纯装饰内容；如果图片承载产品、教程步骤或新闻信息，通常更适合使用语义明确的 `<img>`。

## 确保图片可抓取并持续检查

图片优化完成后，还要确认搜索引擎能够访问资源。常见排查项包括：

- 图片 URL 返回正常的 `200` 状态码，而不是 403、404 或循环重定向。
- `robots.txt` 没有误屏蔽图片目录或图片 CDN。
- CDN 防盗链规则不会拦截正常搜索引擎访问。
- 页面无需登录即可查看，图片也不是仅通过临时签名地址提供。
- HTTP 响应中的 `Content-Type` 与实际格式匹配。
- HTTPS 页面没有引用 HTTP 图片，避免混合内容问题。
- 迁移图片地址时设置合理的永久重定向，并同步更新页面引用。

大型图库、新闻站或电商网站可以在 XML Sitemap 中包含图片信息，帮助搜索引擎发现页面中的重要图片，但 Sitemap 不能保证图片一定被收录。产品、文章、食谱等页面若使用符合规范的结构化数据，也应填写准确的 `image` 属性；这有助于搜索引擎理解内容，但不代表必然获得特殊展示。

上线后可结合 Search Console、服务器日志、Lighthouse 和浏览器开发者工具检查抓取状态、图片流量、LCP、CLS 及资源体积。优先处理首屏大图、访问量高的页面和重复出现的公共组件，比一次性批量修改所有图片更容易衡量效果。

图片优化的核心，是用合适的文件格式和尺寸降低传输成本，用清楚的 HTML 语义说明内容，并确保资源可访问、布局稳定。它可能改善用户体验和搜索引擎理解能力，但最终表现仍取决于页面质量、站点技术状态和搜索需求等多方面因素。
