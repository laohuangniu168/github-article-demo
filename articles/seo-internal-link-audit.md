# 网站内链审计完整流程与方法

{% raw %}

## 审计前先确定范围与目标

内链审计不是简单统计每个页面有多少链接，而是检查站内链接能否帮助搜索引擎发现页面、理解网站结构，并让用户顺畅到达重要内容。

开始前需要明确三件事：

1. **审计范围**：整个主域名、某个子域名，还是博客、产品库等特定目录。
2. **重点页面**：例如核心产品页、栏目页、转化页和持续获得搜索流量的内容。
3. **评估基准**：使用正式环境还是测试环境，是否包含分页、多语言页面及参数 URL。

建议先建立重点 URL 清单，并记录页面类型、索引需求和业务优先级。后续发现孤立页面或链接层级过深时，才能判断它们是否真的需要修复。

同时检查抓取工具是否受到以下设置影响：

- `robots.txt` 是否阻止了相关目录；
- 页面是否需要登录或依赖 Cookie；
- 导航链接是否由 JavaScript 动态生成；
- 是否存在多个协议、子域名或带参数版本；
- 测试环境与线上环境的内链结构是否一致。

如果站点依赖客户端渲染，应使用支持 JavaScript 渲染的爬虫进行补充检查，但也要确认链接最终以可识别的 `<a href="...">` 形式出现。

## 抓取网站并合并数据来源

可使用 Screaming Frog、Sitebulb 等爬虫获取站内 URL、状态码、链接来源、点击深度和锚文本。小型网站也可以配合浏览器插件或自写脚本，但需要处理相对路径、重定向和 URL 规范化。

一次基础抓取至少应导出：

- 全部内部 HTML 页面；
- 每个 URL 的状态码；
- 入链数量与出链数量；
- 链接来源页面；
- 锚文本及链接属性；
- 页面标题、Canonical 和 robots 指令；
- 从首页计算的点击深度。

仅依赖爬虫会漏掉没有任何可抓取入口的页面，因此还应合并：

- XML Sitemap 中的 URL；
- Google Search Console 导出的页面数据；
- 分析工具中有访问记录的落地页；
- 服务器日志中被搜索引擎访问过的 URL；
- CMS 导出的已发布内容清单。

将这些 URL 统一协议、主机名、末尾斜杠和大小写规则，再按照完整 URL 去重。可在表格中增加“是否被爬虫发现”“是否在 Sitemap”“是否有流量”等字段。

例如，某个 URL 出现在 Sitemap 和分析数据中，却没有出现在站内抓取结果中，它很可能是孤立页面；但也可能被 `robots.txt` 阻止，因此不能只凭单一字段下结论。

## 检查可抓取性与链接错误

先处理影响范围明确的技术问题，因为它们会干扰后续结构判断。

### 失效链接与重定向链

筛选内部链接目标中的 `4xx`、`5xx` 和非预期 `3xx`：

- 已删除且无替代内容的链接，应从来源页面移除；
- 有对应新页面时，直接把内链改为最终 URL；
- 避免“旧地址 → 中间地址 → 最终地址”的重定向链；
- 不要把所有失效 URL 统一跳转到首页，这可能造成语义不匹配。

站内链接即使能够通过 301 到达正确页面，也建议直接指向最终地址，以减少跳转并保持结构清晰。

### 不可索引目标

检查内链是否大量指向以下页面：

- 带有 `noindex` 的页面；
- Canonical 指向其他 URL 的重复页面；
- 被 `robots.txt` 阻止的地址；
- 登录页、筛选参数页和站内搜索结果页；
- HTTP、非首选域名或大小写错误版本。

这些页面不一定都要删除内链。例如登录页对用户仍有价值，但通常不应占据正文中的主要推荐位置。审计重点是确认链接用途与页面索引策略是否一致。

还要识别“软 404”：页面返回 200 状态码，但正文显示内容不存在或已下架。此类页面不会被普通状态码筛选直接发现，需要结合标题、正文模板或 Search Console 报告检查。

## 评估孤立页面、深度与链接分布

### 孤立页面

孤立页面是存在于站点数据源中，却没有可抓取内部链接指向的页面。处理方式取决于页面价值：

- 仍有搜索或业务价值：从相关栏目、专题或正文增加自然入口；
- 内容重复或过时：合并到更合适的页面，并按实际情况重定向；
- 不应公开：从 Sitemap 移除，并设置合理的访问或索引控制；
- 活动结束但仍有参考价值：改为归档页，并从相关历史内容链接。

不要为了消除“孤立”标签，把页面批量塞进页脚。链接所在位置和上下文比单纯增加数量更重要。

### 点击深度

点击深度是从抓取起点到目标页面所需的最少链接次数。核心页面通常应从首页、主导航或重要栏目较容易到达，但不存在适用于所有网站的固定层级标准。

如果重要页面层级过深，可以考虑：

- 完善分类页与子分类页；
- 在相关内容中增加上下文链接；
- 建立专题页或内容中心；
- 增加面包屑导航；
- 修正只能通过站内搜索访问的页面。

分页结构也应纳入检查。不要只链接第一页和最后一页，导致中间页面难以发现；同时避免生成近乎无限的筛选组合。

### 入链分布

按页面类型比较内部入链数量，比全站使用同一阈值更合理。一个新发布的专业文章可能只需要少量高相关链接，而核心分类页通常应获得更多稳定入口。

重点寻找两类异常：

1. 重要页面几乎没有入链；
2. 低价值参数页获得大量模板化链接。

入链数量不能直接等同于页面权重，也不能单独用于预测排名，应结合链接来源的重要性、位置和相关性判断。

## 审查锚文本与链接位置

导出目标 URL、来源 URL、锚文本和链接位置，检查锚文本是否能说明目标内容。常见问题包括：

- 大量使用“点击这里”“了解更多”等模糊文字；
- 锚文本描述与目标页面内容不一致；
- 同一段落重复链接到同一目标；
- 为追求关键词而使用生硬、完全相同的锚文本；
- 图片链接缺少有意义的 `alt` 文本；
- 模板导航产生大量无实际帮助的重复链接。

正文中的链接应服务于阅读路径。例如，介绍“如何配置 301 重定向”时，可以链接到对应教程，而不是强行链接到宽泛的 SEO 首页。

同一 URL 使用多个自然变体通常没有问题。锚文本应准确、简洁并符合上下文，不需要刻意追求完全匹配。还要区分导航、面包屑、正文推荐和页脚链接，因为它们承担的用户功能不同。

## 制定修复顺序并复查结果

可以按照“影响范围 × 页面价值 × 修复成本”排序：

1. 全站模板中的失效链接和错误域名；
2. 核心页面的孤立、重定向或不可索引问题；
3. 重要栏目层级过深、分页断裂；
4. 正文链接相关性与锚文本问题；
5. 低价值页面的局部优化。

修复时建立记录表，至少包含问题 URL、来源页面、问题类型、处理方式、负责人和完成日期。批量修改导航或模板前，应先在少量页面测试，防止产生新的循环重定向、错误相对路径或参数链接。

上线后重新抓取，并与审计前数据对比：

- 失效内部链接是否减少；
- 重点页面是否获得有效入口；
- 孤立页面是否被合理链接、合并或下线；
- 点击深度是否符合网站结构；
- Sitemap、Canonical 与实际内链是否一致；
- 是否出现新的重复 URL。

随后可结合 Search Console 的索引状态、抓取情况和页面表现持续观察。搜索引擎重新处理链接需要时间，数据变化也不代表排名必然变化。一次完整的内链审计应形成可重复的流程：定期抓取、合并数据、识别异常、按优先级修复并复查，而不是一次性增加大量链接。
