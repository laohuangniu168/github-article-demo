# 百度蜘蛛低价值页面抓取控制方法

{% raw %}

## 先判断哪些页面属于低价值页面

控制抓取的目的不是让百度蜘蛛“少来”，而是减少其在重复、无内容或无搜索需求页面上的消耗，把服务器与站内链接资源更多留给重要内容。

常见的低价值页面包括：

- 站内搜索结果页，如 `/search?q=关键词`
- 排序、筛选产生的组合 URL，如 `?sort=price&color=red`
- 日历翻页、无限分页和会话参数页面
- 内容完全相同但参数不同的重复 URL
- 无实际内容的标签页、作者页或空列表页
- 登录、购物车、个人中心等非公开页面
- 已删除、软 404 或反复重定向的 URL
- 测试目录、打印版页面和临时生成页面

不能只根据流量低就认定页面低价值。部分冷门产品页、长尾问答页虽然访问量不高，但内容独立，且可能满足明确需求。处理前应同时检查内容是否重复、是否有搜索需求、是否承担导航功能，以及是否已经获得收录和外链。

## 通过访问日志确认百度蜘蛛的抓取浪费

仅查看百度搜索资源平台中的统计还不够，服务器访问日志能够直接反映蜘蛛正在请求哪些 URL。可先筛选 User-Agent 中包含 `Baiduspider` 的记录，再按 URL 和状态码汇总。

例如，在常见日志环境中可以进行初步筛选：

```bash
grep -i "Baiduspider" access.log > baiduspider.log
```

重点观察以下指标：

1. **抓取次数最多的目录和参数**
   如果筛选参数页面占据大量请求，通常说明抓取空间正在被重复 URL 消耗。

2. **HTTP 状态码分布**
   大量 301、302、404、410 或 5xx 请求，意味着链接结构、删除策略或服务器稳定性需要处理。

3. **重复 URL 形态**
   检查大小写、末尾斜杠、HTTP 与 HTTPS、不同主机名以及无意义参数是否生成同一内容。

4. **重要页面的抓取频率**
   不能只看低价值页面数量，还要确认新文章、商品页和更新页面是否能被正常发现。

需要注意，User-Agent 可以伪造。若日志分析涉及安全判断，可结合来源 IP 的反向解析与正向解析进行验证，不应把所有自称 Baiduspider 的请求都当作真实百度蜘蛛。

## 使用 robots.txt 限制明确无需抓取的区域

对于长期存在、无需出现在搜索结果中的整类 URL，可以在网站根目录的 `robots.txt` 中设置抓取限制。例如：

```txt
User-agent: Baiduspider
Disallow: /search
Disallow: /user/
Disallow: /cart/
Disallow: /print/
Disallow: /*?sort=
Disallow: /*&sort=

Sitemap: https://www.example.com/sitemap.xml
```

该文件应能够通过以下地址直接访问：

```txt
https://www.example.com/robots.txt
```

配置时应遵循几个原则：

- 优先屏蔽规则稳定的目录和参数，不要逐条罗列成千上万个 URL。
- 修改前检查规则覆盖范围，避免误伤文章、商品详情或静态资源。
- CSS、JavaScript 如果参与页面内容呈现，不应随意屏蔽。
- Sitemap 中只保留规范、可访问且希望搜索引擎处理的 URL。
- 发布后继续观察日志，因为已经排队的 URL 可能仍会在一段时间内出现请求。

`robots.txt` 控制的是抓取权限，不等于删除收录。某个 URL 即使被禁止抓取，百度仍可能通过站内链接或外链知道它的存在。因此，已经收录且需要删除的页面，不应只依赖 `Disallow`。

## 从链接与 URL 生成源头减少重复页面

robots.txt 是拦截层，真正有效的长期治理应从 URL 生成和站内链接开始。如果网站持续输出大量参数链接，蜘蛛仍会反复发现这些地址。

### 统一规范 URL

同一内容应尽量只保留一个可索引地址，例如统一：

- HTTP 或 HTTPS
- `www` 或非 `www`
- URL 大小写
- 末尾斜杠规则
- 默认首页文件，如 `/index.html`
- 无意义跟踪参数，如 `utm_source`

非规范地址可通过 301 重定向到主地址。对于必须保留但内容重复的页面，可在 HTML 的 `<head>` 中声明规范页：

```html
<link rel="canonical" href="https://www.example.com/product/123">
```

Canonical 是规范化提示，不是强制禁止抓取。百度需要先访问页面才能看到该标签，因此不宜一开始就用 robots.txt 屏蔽这些重复页，否则搜索引擎可能无法读取规范声明。

### 控制筛选与搜索链接

商品筛选页面容易形成组合爆炸。可以只为具有稳定搜索需求的分类组合生成可访问链接，其他条件使用表单、前端交互或不产生可抓取 URL 的实现方式。对无价值组合，不要在导航、面包屑和推荐模块中持续输出链接。

链接上的 `rel="nofollow"` 可以作为辅助信号，但不能保证目标 URL 不被发现或抓取。如果该地址还出现在 Sitemap、外链或其他普通链接中，蜘蛛仍可能访问。

## 对删除页、空页和异常页返回正确状态码

状态码决定搜索引擎如何理解页面。低价值页面治理中，最常见的问题是所有不存在的 URL 都返回 `200 OK`，并展示“内容不存在”。这类软 404 页面既浪费抓取，也可能造成大量无效收录。

建议按实际情况处理：

| 页面情况 | 推荐处理 |
|---|---|
| 内容永久删除且无替代页 | 返回 404 或 410 |
| 内容迁移到明确的新地址 | 301 到最相关的新页面 |
| 临时维护后会恢复 | 返回 503，并合理设置重试时间 |
| 参数 URL 与主页面内容相同 | 规范化或 301 |
| 空分类短期内会补充内容 | 可保留，但应提供有效信息并避免批量创建 |
| 服务器故障 | 修复 5xx，不要伪装成 200 |

不要把所有删除页面都重定向到首页。大量无关 301 既不能保留页面相关性，也会让搜索引擎难以判断真实状态。

如果已删除 URL 数量较大，可以在确认返回 404 或 410、并清除站内链接和 Sitemap 记录后，再查看百度搜索资源平台当前是否提供相应的死链提交入口。工具提交只能辅助发现，正确状态码和持续可访问的错误响应仍是基础。

## 分阶段实施并持续验证结果

抓取控制适合按“发现—分类—处理—验证”的顺序推进，而不是一次性大范围屏蔽。

第一阶段先导出一至四周日志，找出高频参数、异常目录和状态码。第二阶段按照页面类型分别采用链接清理、301、Canonical、404/410 或 robots.txt。第三阶段检查重要页面是否仍可通过导航和 Sitemap 被发现。最后持续比较调整前后的抓取结构。

验证时应关注：

- 低价值 URL 的请求占比是否下降
- 重要内容的抓取是否保持正常
- 404、重定向链和 5xx 是否减少
- Sitemap 是否仍包含被屏蔽或已删除地址
- 新规则是否误拦截详情页及渲染资源
- 服务器负载是否得到改善

抓取频率变化通常不会立即完成，也不能直接等同于排名或收录提升。更稳妥的目标是建立清晰、稳定且可解释的 URL 体系：让百度蜘蛛容易发现重要页面，对重复页面有明确规范，对删除页面获得正确状态，并从源头停止制造新的无效链接。
