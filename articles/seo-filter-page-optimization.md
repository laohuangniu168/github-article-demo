# 网站筛选页面SEO优化策略

{% raw %}

筛选功能可以帮助用户快速缩小商品或内容范围，但颜色、品牌、价格、排序等条件自由组合后，往往会产生大量相似 URL。若不加控制，搜索引擎可能反复抓取低价值页面，分散站内链接信号，并增加重复内容与索引膨胀风险。

优化的核心不是“让所有筛选页都收录”，而是先判断哪些组合具有独立搜索需求，再为不同类型的 URL 制定抓取、索引和规范化策略。

## 先对筛选页面进行价值分类

不要按技术参数统一处理所有页面。建议结合搜索需求、商品数量、内容差异和转化价值，将筛选组合分成三类。

| 页面类型 | 示例 | 建议方向 |
|---|---|---|
| 有明确搜索需求 | 女士跑步鞋、适合学生的笔记本电脑 | 可建设为可索引落地页 |
| 有一定浏览价值但搜索需求弱 | 黑色耐磨女士跑步鞋 | 通常允许用户访问，但谨慎开放索引 |
| 几乎没有独立价值 | 按价格排序、同时选择多个冷门参数 | 不作为搜索落地页 |

判断时可以查看关键词工具、站内搜索词、广告搜索词报告、历史自然流量和转化数据。只有当一个筛选组合能够满足独立意图，并且结果数量相对稳定时，才值得建设成索引页面。

还要设定结果数量门槛。例如，某个分类筛选后长期只有一两个商品，页面容易变成薄内容；若商品下架后直接成为空结果页，也不适合作为长期入口。具体门槛应根据品类规模确定，而不是机械使用固定数字。

## 设计稳定且可区分的 URL

筛选 URL 应保持规则一致，避免同一条件因参数顺序、大小写或默认值产生多个地址。例如：

```text
/category/shoes?brand=nike&color=black
/category/shoes?color=black&brand=nike
/category/shoes?brand=Nike&color=black&sort=default
```

如果三者展示相同内容，应在应用层统一参数顺序、大小写和默认值，并通过 301 重定向或规范链接集中到一个首选 URL。

参数也应按功能区分：

- **筛选参数**：品牌、颜色、尺寸、用途；
- **排序参数**：价格升降序、销量、新品；
- **展示参数**：列表或网格、每页数量；
- **追踪参数**：UTM、广告点击标识；
- **分页参数**：页码或游标。

排序、展示和追踪参数通常不改变页面主题，不应被视为新的搜索落地页。对确有搜索价值的筛选组合，可以创建简洁、固定的路径，例如：

```text
/shoes/women/
/shoes/women/running/
/shoes/women/running/nike/
```

但不必把所有参数都改成目录形式。路径美观并不能解决页面重复问题，关键仍是组合是否值得被抓取和索引。

## 分别处理抓取、索引与规范化

这三个概念不能混用：

- `robots.txt` 主要控制抓取；
- `noindex` 控制页面是否进入索引；
- `rel="canonical"` 用于声明首选版本，但搜索引擎可能根据实际情况选择其他规范页。

对于需要保留给用户、但不希望出现在搜索结果中的筛选页，可以返回正常的 HTTP 200 状态，并设置：

```html
<meta name="robots" content="noindex,follow">
```

搜索引擎需要先抓取页面，才能看到 `noindex`。因此，不要同时在 `robots.txt` 中屏蔽该 URL，否则爬虫可能无法读取页面上的索引指令。

如果多个 URL 的主体内容实质相同，例如只是排序方式不同，可以指向默认分类页：

```html
<link rel="canonical" href="https://www.example.com/shoes/women/">
```

但不要把所有筛选页无差别 canonical 到上级分类。若“女士跑步鞋”和“女士高跟鞋”结果及意图明显不同，错误的规范声明可能不会被采纳，也会让搜索引擎更难理解页面结构。

对于无限参数组合、爬虫陷阱或已确认没有抓取价值的路径，可考虑通过 `robots.txt` 限制抓取，例如：

```text
User-agent: *
Disallow: /*?sort=
Disallow: /*&sort=
Disallow: /*?view=
Disallow: /*&view=
```

配置前应检查参数可能出现的位置和站点 URL 规则，避免误伤需要收录的页面。`robots.txt` 也不是删除已收录 URL 的工具；已进入索引的页面应先允许抓取并返回 `noindex`，待索引状态更新后再评估是否限制抓取。

## 为可索引筛选页补足独立价值

决定开放索引后，页面不能只更换商品列表。应让标题、主标题、说明文字和内部链接共同表达明确主题。

例如“女士跑步鞋”页面可以配置：

```html
<title>女士跑步鞋选购与热门款式 - 示例商城</title>
<meta name="description" content="查看适合日常慢跑与训练的女士跑步鞋，可按品牌、尺码和缓震类型继续筛选。">
<h1>女士跑步鞋</h1>
```

页面还可以增加简短的选购提示、适用场景、尺码说明或常见问题，但内容应服务于用户决策，不能只批量替换品牌和颜色生成近似文案。

同时注意以下细节：

1. 首屏应能看到与筛选条件一致的结果；
2. 空结果页不要继续返回可索引模板，可移除索引资格，必要时返回 404 或 410；
3. 长期下架且没有替代内容的落地页，应根据业务情况重定向或下线；
4. 面包屑和页面标题要体现当前层级；
5. 结构化数据必须与页面实际可见内容一致，不能标记不存在的商品或评分。

## 优化内链与分页发现方式

搜索引擎通常通过站内链接判断页面重要性。值得收录的筛选页应从分类导航、专题页、正文推荐或 HTML 站点地图获得可抓取链接，而不是只能通过提交表单或执行复杂 JavaScript 才能访问。

普通链接应使用真实的 `<a href>`：

```html
<a href="/shoes/women/running/">女士跑步鞋</a>
```

对于不准备收录的任意组合，不要在全站模板中生成海量可抓取链接。可以只展示高价值筛选项，或让低价值交互不产生新的永久 URL，但不能因此破坏用户返回、分享和无障碍访问。

分页页面通常应拥有可访问的独立 URL，例如 `?page=2`。每一页应自引用 canonical，不宜全部指向第一页，否则后续商品可能更难被发现。还应提供可抓取的上一页、下一页或页码链接。若使用“加载更多”或无限滚动，建议同时提供对应的分页 URL，确保不执行 JavaScript 时仍有发现路径。

## 上线后持续监测并调整规则

筛选策略需要根据实际抓取和索引数据修正。上线后可重点检查：

- 搜索引擎抓取统计中，参数 URL 是否占用过多抓取量；
- 站点日志里，爬虫是否反复访问无结果或超深组合；
- Search Console 的网页索引报告中，重复页、替代页和已抓取未编入索引页面是否异常增长；
- XML Sitemap 是否只提交规范、可索引且返回 200 的 URL；
- 可索引筛选页是否获得展示、点击和转化；
- 商品数量变化后，页面是否变成空页或薄内容。

抽样检查时，应同时核对 HTTP 状态码、robots 指令、canonical、页面标题、实际结果和内部链接，不能只看浏览器地址栏。

更稳妥的做法是建立筛选白名单：默认不开放任意组合，仅将经过需求验证、内容充足且可长期维护的页面加入索引体系。这样既保留筛选功能的用户体验，也能减少重复 URL 和无效抓取。最终目标不是扩大页面数量，而是让每个可被搜索发现的筛选页都对应清晰、稳定且有实际价值的搜索需求。
