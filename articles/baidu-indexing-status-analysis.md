# 百度网站收录状态分析与排查方法

{% raw %}

判断百度是否收录网站，不能只看 `site:` 查询结果。一个页面从上线到出现在搜索结果中，通常要经历“发现链接、抓取页面、内容处理、建立索引、搜索展现”几个阶段。任何环节出现问题，都可能表现为搜不到页面。排查时应先确认问题属于抓取、索引还是展现，而不是反复提交链接。

## 先区分抓取、索引与搜索展现

这三个概念容易混淆：

- **已抓取**：百度蜘蛛访问过 URL，服务器日志中可能留下请求记录，但不代表页面已进入索引。
- **已索引**：页面内容经过处理后进入百度索引库，具备参与搜索排序的可能。
- **有展现**：用户搜索相关词时页面实际出现在结果中。已索引页面不一定在每次查询中展现。
- **有排名**：页面在特定关键词下获得可见位置，这还与相关性、内容质量、站点信誉和竞争程度有关。

因此，“搜索完整标题找不到”不能直接证明页面未收录。标题可能被改写，页面也可能因结果去重、相关性不足或排名靠后而暂时不可见。

如果网站已接入百度搜索资源平台，应优先查看其中的**索引量**数据。该数据更适合判断整体趋势，但通常存在统计延迟，不宜用来确认刚发布几分钟或几小时的页面。

## 使用多种方法确认收录状态

### 1. 使用 site 指令做快速检查

在百度搜索框中输入：

```text
site:example.com
```

查询具体目录或页面时，可以尝试：

```text
site:example.com/news/
site:example.com 完整页面标题
```

`site:` 适合快速观察，但结果数量是估算值，也可能受到结果过滤影响，不能当作网站真实索引总量。带不带 `www`、HTTP 与 HTTPS、主域名与子域名还应分别检查，避免遗漏不同站点版本。

### 2. 查看百度搜索资源平台

完成站点验证后，重点关注：

- 索引量是否长期为零；
- 索引量从某一天开始明显下降；
- HTTP 与 HTTPS 站点是否添加正确；
- 是否存在抓取异常或 robots 限制；
- 链接提交记录是否成功接收。

提交成功只表示百度接收到 URL，不等于已经抓取或收录。平台数据也可能晚于服务器日志和线上变化，应结合时间线判断。

### 3. 搜索页面特征内容

复制页面中一段较独特的文字进行搜索，比只搜索标题更有参考价值。若结果展示了其他网站而没有原页面，可能存在转载页先被发现、原页面抓取困难或内容重复度较高等情况。

## 判断问题是整站还是局部页面

排查前先划定范围，可以显著减少无效操作。

### 整站几乎没有收录

常见原因包括：

1. 新站尚未被发现或抓取频率较低；
2. `robots.txt` 错误屏蔽了全站；
3. 首页返回异常状态码；
4. 域名解析不稳定，百度蜘蛛无法连接；
5. 网站必须登录、验证或执行复杂脚本才能看到正文；
6. HTTPS 证书、跳转链或主机配置异常；
7. 站点曾长期关闭，恢复后仍处于重新抓取阶段。

### 只有部分目录或页面不收录

应重点比较已收录页面与未收录页面的差异：

- 是否属于同一目录或模板；
- 内链入口是否足够明确；
- 页面是否只有筛选参数、空列表或少量重复文字；
- canonical 是否指向其他 URL；
- 分页、标签页是否产生大量近似内容；
- 页面是否返回 200，但正文实际显示“内容不存在”；
- 新页面是否只能通过站内搜索找到。

如果问题集中发生在一次改版、HTTPS 切换或 URL 规则调整之后，应先检查迁移映射和重定向，而不是继续批量生成新页面。

## 检查抓取与服务器技术配置

首先检查 URL 的实际响应：

```bash
curl -I -L --max-redirs 5 https://example.com/page
```

正常内容页通常应最终返回 `200`。其他状态需要结合用途判断：

- `301`、`308`：永久跳转，应确认目标地址正确且没有多层跳转；
- `302`、`307`：临时跳转，不适合长期替代固定页面；
- `404`、`410`：页面不存在；
- `403`：访问被拒绝，可能是防火墙或安全策略拦截；
- `429`：请求过多，限速规则可能过严；
- `5xx`：服务器或网关异常。

还要访问：

```text
https://example.com/robots.txt
```

检查是否存在类似配置：

```text
User-agent: *
Disallow: /
```

这会阻止匹配该规则的搜索引擎抓取全站。修改 robots 后，旧的抓取状态不会立即消失，搜索引擎需要重新访问并处理。

服务器日志是判断“百度有没有来过”的重要依据。可搜索包含 `Baiduspider` 的请求记录，并观察访问时间、URL、响应码和耗时。不过 User-Agent 可以伪造，如需确认来源，应结合 IP 的反向解析与正向解析结果，而不是只看名称。

同时检查 CDN、WAF、防盗链和地域访问策略。真实用户访问正常，并不代表搜索引擎请求一定正常。不要专门向蜘蛛返回与用户明显不同的正文，这可能造成内容识别和质量判断问题。

## 排查页面自身的索引障碍

技术上能访问之后，还要确认页面是否值得被独立索引。

### 检查源码中的控制信号

查看页面源代码，重点寻找：

```html
<meta name="robots" content="noindex">
<link rel="canonical" href="https://example.com/other-page">
```

如果页面被设置为 `noindex`，或 canonical 长期指向其他页面，搜索引擎可能不会将当前 URL 作为主要索引地址。canonical 更接近规范化提示，并非强制命令，但错误配置仍会造成判断混乱。

还应确认：

- canonical 使用完整且可访问的 HTTPS 地址；
- 移动端与桌面端没有互相指向错误页面；
- 页面标题、正文和 canonical 未被模板统一写成首页信息；
- 正文直接存在于返回的 HTML 中，或至少不依赖用户点击后才加载。

纯客户端渲染、接口失败、首屏只有空容器等情况会增加抓取和解析难度。重要正文、标题和主要链接尽量在初始 HTML 中可读取。

### 评估页面是否具有独立价值

以下页面即使能抓取，也可能不进入有效索引：

- 大量城市名或关键词替换生成的模板页；
- 只有几行文字的空分类页；
- 参数不同但内容相同的 URL；
- 聚合转载且缺少来源、分析或补充信息的页面；
- 已过期、失效或与站内其他页面高度重复的内容。

处理方法不是简单“增加字数”，而是明确页面解决的问题，补充真实数据、步骤、示例、适用条件和更新时间。对于无独立价值的参数页，应减少生成和内链暴露，必要时合并到规范页面。

## 按优先级修复并观察变化

建议按以下顺序执行：

1. **确保可访问**：修复 DNS、证书、5xx、403、错误跳转和超时。
2. **解除抓取限制**：核对 robots、登录墙、WAF 与限速策略。
3. **统一 URL**：确定 HTTP/HTTPS、主域名、尾斜杠和参数规则，设置合理跳转与 canonical。
4. **完善发现路径**：从首页、栏目页或相关文章添加可抓取的 HTML 链接。
5. **改进页面内容**：合并重复页，补充真正有用的信息，删除或修复软 404 页面。
6. **提交重要 URL**：使用百度搜索资源平台中当前可用的链接提交方式，优先提交新页面和重大更新页面，避免无意义地反复提交。
7. **持续观察**：记录修复日期，对照索引量、日志抓取、状态码和搜索展现变化。

观察周期应根据网站规模、抓取频率和问题类型决定。新站、低频更新站点或大规模 URL 改版通常需要更长时间重新处理。提交链接、更新 Sitemap 或增加内链都有助于搜索引擎发现页面，但不能保证收录或排名。

有效的排查结论应能回答三个问题：百度是否发现了 URL、抓取时得到什么响应、页面为何值得作为独立结果保留。先解决访问和索引控制问题，再处理内容质量与站内结构，才能避免把技术故障误判成内容问题，也避免把正常的数据延迟当成惩罚。
