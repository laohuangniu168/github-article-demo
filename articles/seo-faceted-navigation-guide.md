# 筛选导航Faceted Navigation SEO优化指南

{% raw %}

## 筛选导航为什么容易产生 SEO 问题

筛选导航（Faceted Navigation）允许用户按品牌、价格、颜色、尺寸、地区等条件缩小结果范围。它能改善商品发现效率，但每一种条件及其组合都可能生成独立 URL，例如：

```text
/shoes/
/shoes/?brand=nike
/shoes/?color=black&size=42
/shoes/?size=42&color=black
/shoes/?brand=nike&sort=price_desc
```

如果条件可以自由组合，数十个筛选项就可能产生数万甚至更多 URL，常见问题包括：

- **重复或近似内容**：参数顺序不同，但页面内容相同。
- **抓取资源浪费**：搜索引擎持续抓取排序、视图切换和无结果页面。
- **索引膨胀**：大量低价值组合页进入索引，稀释网站整体质量信号。
- **权重分散**：内部链接指向多个等价 URL，外链也可能落到不同参数版本。
- **重要页面发现变慢**：新品、分类页等核心 URL 的抓取可能受到影响。

优化目标不是简单禁止所有筛选页，而是区分：哪些组合具有独立搜索需求，哪些只服务于站内用户。

## 先建立筛选 URL 的索引规则

建议先按搜索价值和页面质量对筛选条件分类，再决定是否允许索引。

| 页面类型 | 常见处理方式 |
|---|---|
| 核心分类页 | 允许抓取和索引，使用自引用 canonical |
| 有稳定需求的品牌、属性组合页 | 建立静态落地页，允许索引 |
| 排序、展示方式、每页数量参数 | 通常不索引，并减少可抓取链接 |
| 多条件任意组合页 | 多数设置为不索引 |
| 搜索结果页、无结果页 | 通常不索引 |
| 跟踪参数产生的重复 URL | 规范到不含跟踪参数的版本 |
| 分页页面 | 保留可抓取性，根据内容设置自引用 canonical |

判断一个筛选页是否值得索引，可以检查以下条件：

1. 是否存在明确、持续的搜索需求，例如“黑色男士跑鞋”。
2. 页面是否有足够的商品或内容，而不是长期只有一两个结果。
3. 标题、主标题、说明文字能否与其他组合页形成实质差异。
4. 商品集合是否稳定，是否会频繁变为空页面。
5. 网站是否能持续维护该 URL 的内链、状态码和元数据。

有价值的组合最好转为规则清晰的静态路径，例如：

```text
/running-shoes/nike/
/running-shoes/black/
```

静态路径本身不会自动获得更好的排名，但通常比无规则参数更容易管理、分享和建立内部链接。

## 正确使用 canonical、noindex 与 robots.txt

这三个工具解决的问题不同，不能互相替代。

### canonical：合并重复版本的信号

如果参数只改变排序方式，可以在参数页指向主分类页：

```html
<link rel="canonical" href="https://example.com/shoes/">
```

canonical 是规范化提示，不是强制指令。若参数页的商品集合与分类页差异很大，搜索引擎可能不接受该指向。真正希望独立索引的品牌或属性页，应使用自引用 canonical：

```html
<link rel="canonical" href="https://example.com/running-shoes/nike/">
```

生成 canonical 时应统一协议、主机名、大小写、尾部斜杠和参数顺序，并避免指向重定向、404 或被阻止抓取的 URL。

### noindex：允许访问，但不进入索引

对用户有用、却没有独立搜索价值的筛选组合，可以返回：

```html
<meta name="robots" content="noindex,follow">
```

搜索引擎需要抓取页面才能看到 `noindex`。因此，不要同时在 `robots.txt` 中禁止该 URL，否则爬虫可能无法读取该指令。长期来看，带有 `noindex` 的页面链接是否继续被跟踪由搜索引擎自行判断，重要页面不应依赖这些链接作为唯一入口。

### robots.txt：控制抓取，而不是删除索引

对于会无限生成、没有抓取价值的固定参数模式，可以谨慎限制：

```text
User-agent: *
Disallow: /*?sort=
Disallow: /*&sort=
Disallow: /*?view=
Disallow: /*&view=
```

规则必须结合网站真实 URL 测试。参数可能出现在不同位置，仅写一种形式容易遗漏。`robots.txt` 不能保证已收录 URL 从索引中消失，也不适合阻止包含关键内容或 canonical 指令的页面。

## 控制 URL 生成与内部链接

最有效的治理通常发生在网站架构层，而不是依赖搜索引擎事后处理。

### 统一参数规则

为同一筛选状态只生成一个 URL：

- 固定参数名称和排列顺序。
- 同一属性不同时使用 `color=black`、`colour=black` 等写法。
- 删除空参数、默认值和无业务意义的会话参数。
- 大小写保持一致。
- 跟踪参数不要进入站内导航链接。

例如将以下多个版本统一：

```text
/shoes/?size=42&color=black
/shoes/?color=black&size=42
/shoes/?color=black&size=42&utm_source=nav
```

规范为：

```text
/shoes/?color=black&size=42
```

非规范版本可通过 301 重定向归并；如果参数仍有分析用途，也可保留访问，但输出正确 canonical。

### 限制可组合深度

并非每个筛选按钮都必须输出普通 `<a href>` 链接。建议：

- 为核心分类、品牌和高价值属性提供可抓取链接。
- 对排序、库存状态、视图模式使用表单或交互控件。
- 限制同时选择的筛选数量。
- 不链接到零结果或明显过窄的组合。
- 面包屑和主导航优先指向规范 URL。

不要为了阻止抓取而把所有链接改成依赖点击事件的 JavaScript。这样可能同时削弱重要筛选页的发现能力。需要索引的页面应保留稳定、可直接访问的 URL 和标准 HTML 链接。

## 优化可索引筛选落地页

被选中进入索引的页面，应达到普通分类页的质量标准，而不只是替换标题中的属性词。

每个落地页至少需要：

- 唯一且准确的 `<title>` 和 H1。
- 与筛选条件一致的商品列表。
- 简短、有帮助的分类说明，避免批量拼接空洞文案。
- 清晰的面包屑及返回上级分类的链接。
- 合理的缺货处理和替代推荐。
- 自引用 canonical 与可索引的 robots 设置。
- 200 状态码；永久下线时使用合适的 301、404 或 410。

分页页面不应全部 canonical 到第一页，因为后续页包含不同商品。通常可让各分页自引用 canonical，并确保爬虫能通过普通链接访问下一页。无限滚动页面也应提供对应的分页 URL，否则搜索引擎可能无法发现滚动后加载的内容。

XML Sitemap 只提交希望被索引的规范 URL，不要把 `noindex` 页面、重定向 URL、参数重复页或 404 页面放入 Sitemap。

## 上线后的检查与持续监测

筛选导航改动涉及模板、前端和服务器规则，上线前应抽样验证不同类型 URL：

1. 检查状态码、robots meta 和 canonical 是否一致。
2. 确认规范 URL没有跳转链或循环跳转。
3. 测试参数顺序、重复参数和无效属性值。
4. 查看无结果页面是否仍返回 200 并被大量链接。
5. 验证移动端与桌面端生成的 URL 是否相同。
6. 使用抓取工具检查可抓取 URL 数量及层级变化。
7. 在 Google Search Console 中观察网页索引、重复网页、抓取统计和具体 URL 检查结果。
8. 结合服务器日志确认搜索引擎是否反复抓取无价值参数。

调整后不要只看收录数量。更值得关注的是核心分类与落地页能否被稳定发现、重复 URL 是否减少、抓取是否集中到有效页面，以及自然搜索流量和转化是否发生合理变化。

筛选导航 SEO 的关键是建立明确边界：少量有需求、有内容的组合页作为搜索落地页，其余组合服务用户但不参与索引。通过统一 URL、控制链接生成、合理使用 canonical 与 noindex，并持续检查日志和索引报告，才能在用户筛选体验与搜索引擎抓取效率之间取得平衡。
